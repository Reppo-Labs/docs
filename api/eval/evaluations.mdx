An evaluation is asynchronous. You submit it, save the returned `id`, and poll until the status is `COMPLETED` or `FAILED`. All endpoints use the base URL `https://eval.reppo.xyz/api/v1` and an [API key](/api/eval/overview#authentication).

## Submit an evaluation

`POST https://eval.reppo.xyz/api/v1/agents/evals`

Evaluations are queued and scored in the background by a panel of independent evaluators, usually within 30 to 90 seconds. Submitting returns straight away with the evaluation's `id`.

### Request body

<ParamField body="taskType" type="string" required>
  What you're submitting. One of `claim` (a statement to fact-check), `response` (an AI response; include the user's prompt too), or `action` (an agent action; include what the user asked for too).
</ParamField>

<ParamField body="input" type="string" required>
  The submission to evaluate. Non-empty, up to 50 KB.
</ParamField>

<ParamField body="attachments" type="object[]">
  At most one attachment, up to 1.25 MB: `image/png`, `image/jpeg`, `image/webp`, or `application/pdf`. See [Submit with an attachment](#submit-with-an-attachment). The attachment is part of the submission, so say in `input` what to assess about it.
</ParamField>

### Response — `201 Created`

The same shape as the [read response](#read-an-evaluation-result), with `status` set to `QUEUED` and no result yet. Save `id`: that's what you read the result back with.

### Example

```bash
curl -X POST "https://eval.reppo.xyz/api/v1/agents/evals" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "taskType": "response",
    "input": "User prompt: What is 15% of 200?\n\nAI response: 15% of 200 is 35."
  }'
```

### Errors

| Status | Cause |
|---|---|
| `400` | The request body failed validation, or an attachment is missing or too large |
| `401` | Missing or invalid API key |
| `402` | Not enough credits: 440 for a text-only evaluation, 1,000 with an attachment |
| `500` | Unexpected server error |
| `502` | The evaluation couldn't be queued. It's returned as `FAILED` and not charged, so try again. |

## Read an evaluation result

`GET https://eval.reppo.xyz/api/v1/agents/evals/{id}`

Returns one of your own evaluations. Poll it every few seconds until `status` is `COMPLETED` or `FAILED`.

### Path parameters

<ParamField path="id" type="string" required>
  The `id` returned when you submitted.
</ParamField>

### Response — `200 OK`

<ResponseField name="id" type="string">
  The evaluation ID.
</ResponseField>

<ResponseField name="taskType" type="string">
  `claim`, `response`, or `action`.
</ResponseField>

<ResponseField name="source" type="string">
  `WEB`, `API`, or `X402`.
</ResponseField>

<ResponseField name="input" type="string">
  The submitted input.
</ResponseField>

<ResponseField name="status" type="string">
  `QUEUED`, `PROCESSING`, `COMPLETED`, or `FAILED`. See [Evaluation statuses](/api/eval/overview#evaluation-statuses).
</ResponseField>

<ResponseField name="score" type="number | null">
  Overall quality from 0 to 100. `null` until the evaluation is `COMPLETED`.
</ResponseField>

<ResponseField name="route" type="string | null">
  The recommendation: `ship` (good to use), `review` (needs a human look), or `block` (don't use it). `null` until the evaluation is `COMPLETED`.
</ResponseField>

<ResponseField name="creditsCharged" type="number">
  `0` until the evaluation is `COMPLETED`, then the price: `440` for a text-only evaluation, `1000` with an attachment.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO 8601 submission time.
</ResponseField>

<ResponseField name="startedAt" type="string">
  ISO 8601 time scoring started, set once scoring starts.
</ResponseField>

<ResponseField name="completedAt" type="string">
  ISO 8601 completion time, set once the evaluation finishes.
</ResponseField>

<ResponseField name="attachments" type="object[]">
  Attachments, as `{ filename, contentType }`.
</ResponseField>

<ResponseField name="result" type="object | null">
  `null` until the evaluation is `COMPLETED`. Then the verdict object below.

  <Expandable title="Verdict object">
    <ResponseField name="score" type="number">
      0 to 100 overall quality.
    </ResponseField>
    <ResponseField name="decision" type="string">
      `accept` or `reject`, at the policy threshold.
    </ResponseField>
    <ResponseField name="confidence" type="string">
      `low`, `medium`, or `high`: how much the evaluators agreed.
    </ResponseField>
    <ResponseField name="route" type="string">
      `ship`, `review`, or `block`.
    </ResponseField>
    <ResponseField name="reason" type="string">
      A one-paragraph explanation.
    </ResponseField>
    <ResponseField name="rubric_scores" type="object">
      The per-dimension breakdown, for example `{ "accuracy": 85 }`.
    </ResponseField>
    <ResponseField name="consensus" type="object">
      How the evaluators' scores were combined.
    </ResponseField>
    <ResponseField name="explain" type="object">
      `{ confidence_checks, route_reasons }`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="trace" type="object">
  Each evaluator's scores and reasoning.
</ResponseField>

<ResponseField name="error" type="string | null">
  `null` unless the evaluation failed.
</ResponseField>

A `FAILED` evaluation wasn't charged. Submit it again.

### Example

```bash
curl "https://eval.reppo.xyz/api/v1/agents/evals/YOUR_EVAL_ID" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```json
{
  "id": "string",
  "taskType": "response",
  "source": "API",
  "input": "string",
  "status": "COMPLETED",
  "score": 82,
  "route": "ship",
  "creditsCharged": 440,
  "createdAt": "2024-01-01T00:00:00.000Z",
  "startedAt": "2024-01-01T00:00:02.000Z",
  "completedAt": "2024-01-01T00:00:58.000Z",
  "attachments": [],
  "result": {
    "score": 82,
    "decision": "accept",
    "confidence": "high",
    "route": "ship",
    "reason": "string",
    "rubric_scores": { "accuracy": 85 },
    "consensus": {},
    "gates": [],
    "explain": { "confidence_checks": [], "route_reasons": ["string"] }
  },
  "trace": {},
  "error": null
}
```

### Errors

| Status | Cause |
|---|---|
| `401` | Missing or invalid API key |
| `404` | No evaluation with that `id`, or it belongs to a different account |
| `500` | Unexpected server error |

## Submit with an attachment

You can attach one PNG, JPEG, WebP, or PDF file, up to 1.25 MB, to an evaluation. It's evaluated as part of the submission, not as background material. Attaching takes three calls.

<Steps>
  <Step title="Request an upload URL">
    `POST https://eval.reppo.xyz/api/v1/agents/evals/attachments`

    ```bash
    curl -X POST "https://eval.reppo.xyz/api/v1/agents/evals/attachments" \
      -H "Authorization: Bearer YOUR_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{ "filename": "screenshot.png", "contentType": "image/png" }'
    ```

    `filename` is 1 to 255 characters. `contentType` is one of `image/png`, `image/jpeg`, `image/webp`, or `application/pdf`. The response is `{ "key": "string", "uploadUrl": "string" }`. The `uploadUrl` expires in 5 minutes. The 1.25 MB size limit isn't enforced here. It's checked when you submit the evaluation.
  </Step>
  <Step title="Upload the file">
    Send the file bytes straight to `uploadUrl` with `PUT`. The file goes to storage, not through this API. The URL is signed for `PUT` only, so any other method fails signature verification.

    ```bash
    curl -X PUT "UPLOAD_URL_FROM_RESPONSE" \
      -H "Content-Type: image/png" \
      --data-binary "@screenshot.png"
    ```
  </Step>
  <Step title="Submit with the key">
    Submit the evaluation as usual, with the `key` in `attachments`:

    ```json
    {
      "taskType": "response",
      "input": "User prompt: Summarise this chart.\n\nAI response: Revenue grew 40% year on year. Check the summary against the attached chart.",
      "attachments": [
        { "key": "KEY_FROM_STEP_1", "filename": "screenshot.png", "contentType": "image/png" }
      ]
    }
    ```

    The 1.25 MB limit is checked here. A missing or oversized file returns `400`.
  </Step>
</Steps>
